Overview

How it works

  1. Your server calls POST /v1/otp/send with the recipient and a channel (whatsapp, sms or email). You may pass your own code or let OTP88 generate one.
  2. OTP88 delivers the message and returns transactionId, otpCode and the cost. Your balance is charged only when the provider accepts the message.
  3. You store otpCode with the user's session and compare it with what the user types in. Enforce your own expiry window.
  4. Delivery updates (otp.sent, otp.delivered, otp.failed, …) are posted to your webhook URL so you can offer another channel when delivery fails.
Step 1

Authentication & base URL

Every request is JSON over HTTPS and carries your API key as a Bearer token. Keys start with otp88_api_ and are shown in the console under API & Keys. Keep the key on your server; never ship it in a mobile app or browser.

                POST
                
/v1/otp/send

              

              

                Sends one OTP over the chosen channel. Rate limit: 120 requests per minute per API key.
              


              

                
Request body

                

                  

                    
                      
FieldTypeRequiredDescription

                    
                    
                      
tostringYesPhone number in international format (+60123456789). Local Malaysian numbers such as 0123456789 are accepted. For the email channel, an email address.

                      
channelstringYeswhatsapp, sms or email. If omitted and to is an email address, email is assumed.

                      
otpstringNo4 to 8 digits. If omitted, a 6-digit code is generated.

                      
codeLengthnumberNoLength of the generated code, 4 to 8. Default 6.

                      
senderNamestringNoBrand shown in the SMS text and the email subject. Default FlashOTP. WhatsApp uses the provider's approved template.

                      
expiryMinutesnumberNoValidity shown in the message. Default 5. Enforcement is up to your application.

                      
remarkstringNoYour own reference (order id, session id). Stored with the log and echoed in webhooks.

                    
                  

                

                

                  Older integrations may still send phoneNumber, email, code, sender_name or expiry_minutes; these aliases keep working but the names above are preferred.
                

              


              

                

                  

                    
                    
                    
                    
                    
                  

                  

                    

                      
                      
                      
                    

                    
                  

                

                

              

            


            
            

              Email channel
              
Email OTP

              

                Set channel to email and pass an email address in to. Emails are sent from the platform domain, so there is no DNS setup on your side. The sender name and mailbox can be branded per request, or saved once in the console under API & Keys → Custom Email Brand Sender and used as the default.
              


              

                

                  
                    
FieldTypeRequiredDescription

                  
                  
                    
brandNamestringNoDisplay name of the sender, e.g. MyApp. Also used in the default subject and the email body. Falls back to the brand saved in the console.

                    
brandHandlestringNoMailbox on the platform domain. myapp sends as MyApp <myapp@otp88.top>. Letters, numbers, hyphens and underscores, 2 to 32 characters. Falls back to the handle saved in the console, then noreply.

                    
replyTostringNoAddress that receives replies, e.g. your support mailbox.

                    
subjectstringNoCustom subject line. Default: <brandName> verification code: <otp>.

                  
                

              


              

                

                  Example request
                  
                

                
{
  "to": "user@example.com",
  "channel": "email",
  "brandName": "MyApp",
  "brandHandle": "myapp",
  "replyTo": "support@myapp.com",
  "otp": "882910",
  "expiryMinutes": 5,
  "remark": "login-4028"
}

Errors & rate limits

              
Every error has the shape { "success": false, "error": "message" }.

              

                

                  
HTTPMeaningWhat to do

                  
                    
400Missing or invalid fieldThe message names the field. Fix the request.

                    
401Missing or invalid API keyCheck the Bearer token. Keys are shown in the console under API & Keys.

                    
402Insufficient balanceResponse includes currentBalance and required. Top up in the console.

                    
403Account paused or suspendedContact support.

                    
429Rate limit exceeded (120 sends / minute)Retry after the Retry-After header.

                    
502Provider rejected the messageNothing was charged. gatewayResponse holds the provider's reply. Try another channel.

                    
503Service temporarily unavailableRetry with backoff.

                  
                

              

            


            
            

              Integration
              
Webhooks

              

                Set a webhook URL in the console (Webhooks page). OTP88 POSTs a JSON event when a message is sent and again when the provider reports delivery. Answer with any 2xx status within 6 seconds; non-2xx responses are retried twice, after 2 and 6 seconds. Each request carries X-OTP88-Event and X-OTP88-Delivery-Attempt headers.
              

              

                
Event payload

                
{
  "event": "otp.delivered",
  "msgId": "78-1633193001.0602",
  "channel": "sms",
  "recipient": "+60123456789",
  "phoneNumber": "+60123456789",
  "status": "DELIVERED",
  "errorCode": "0",
  "remark": "login-4028",
  "cost": "0.0210",
  "currency": "USD",
  "timestamp": "2026-09-24T09:45:00.000Z"
}

              

              

                

                  
EventStatusChannelsMeaning

                  
                    
otp.sentSENTallThe provider accepted the message. For email this is the final event.

                    
otp.deliveredDELIVEREDWhatsApp, SMSThe handset confirmed delivery.

                    
otp.readREADWhatsAppThe recipient opened the message.

                    
otp.pendingPENDINGWhatsApp, SMSQueued at the carrier; a final event follows.

                    
otp.failedFAILEDWhatsApp, SMSRejected or unreachable. Offer the user another channel.

                    
otp.expiredEXPIREDWhatsApp, SMSThe carrier gave up before delivery.

                  
                

              

              
recipient holds the phone number or email address. phoneNumber carries the same value for older integrations.
